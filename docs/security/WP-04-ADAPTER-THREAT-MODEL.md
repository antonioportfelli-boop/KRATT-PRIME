# WP-04 — Adapter Threat Model

Date: 2026-11-27  
Status: initial architecture baseline; not a completed red-team assessment.

This threat model covers adapter discovery, contract validation, registration, authorization, execution, delivery and reconciliation. A validated manifest is untrusted declaration data until a separate host-controlled trust process accepts its provenance.

| # | Threat | Asset | Threat actor, entry point and precondition | Impact | Prevention | Detection | Recovery | Evidence |
|---:|---|---|---|---|---|---|---|---|
| 1 | Adapter impersonation | Adapter identity and trust registry | Malicious adapter or caller supplies another adapter ID; registry lookup is weak or identity is not source-bound. | Wrong code receives scoped work. | Bind identity to repository, pinned revision, artifact digest and host registration. | Identity/source mismatch audit event. | Disable identity; revoke grants; reconcile work started by the identity. | WP-03 trust registry tested; runtime registration pending. |
| 2 | Capability escalation | Capability registry and provider resources | Adapter declares extra capabilities or caller widens a scope. | Unauthorized read or write. | Server-owned capability catalog; intersect principal, agent, adapter and resource scopes. | Compare declared, granted and effective scopes. | Revoke grant; block adapter; investigate prior effects. | Existing capability helper unit-tested; grant runtime incomplete. |
| 3 | Confused deputy | Principal authority and external resources | Low-privilege caller makes a more privileged adapter act on a resource not bound to the caller's request. | Privileged cross-resource operation. | Bind approval to principal, adapter, operation, resource and request digest. | Audit full decision binding without logging secrets. | Deny and require new request-bound approval. | WP-01 policy primitives and WP-03 dispatch tests. |
| 4 | Tenant boundary bypass | Tenant data and credentials | Missing tenant context or caller supplies another tenant identifier. | Cross-tenant disclosure or mutation. | Mandatory tenant ID in every identity, grant, event, outbox, ACK and store key; reject missing context. | Cross-tenant denial and consistency checks. | Quarantine affected work; revoke scoped grants; investigate access. | Tenant boundary not implemented in reviewed core. |
| 5 | Replay attack | Event, approval and webhook nonce state | Captured signed request or callback is resubmitted within or after its validity window. | Repeated handler or side effect. | Nonce/replay ledger, expiry, request digest and durable deduplication. | Duplicate/replay conflict counters and audit. | Return persisted result or reject; do not re-run handler. | WP-03.8 receiver replay and ACK tests. |
| 6 | Forged ACK | Outbox terminal state and event integrity | Untrusted sender supplies a success JSON or signs with an unknown key. | False DONE/COMPLETED state. | Verify Ed25519 signature, digest, receiver key, event identity, attempt and policy revision transactionally. | ACK verification failure and trust audit. | Keep intent unresolved; reconcile from authenticated provider evidence. | WP-03.9 PostgreSQL ACK integration tests. |
| 7 | Reused credential | Provider account and secret references | Credential is copied from logs, a worker environment or another adapter. | Unauthorized provider access. | Opaque references, least privilege, per-adapter isolation and short-lived brokered credentials. | Credential-use audit and anomalous scope monitoring. | Revoke broker reference and investigate; never print the value. | Credential broker not implemented or live-tested. |
| 8 | Revoked credential | Provider account and remote authorization | Revocation occurs while a worker holds a stale credential reference. | Calls continue after revocation. | Resolve credential at use time; revocation fence immediately before dispatch. | Revocation-denied audit and provider 401/403 classification. | Stop dispatch and reconcile any in-flight unknown result. | WP-03 key revocation tested for Fabric keys; provider credentials unconfigured. |
| 9 | Malformed payload | Parser and worker memory | Attacker sends oversized, malformed, deeply nested or ambiguous payload. | Parser crash, memory exhaustion or validation bypass. | Byte limits, closed schemas, depth limits and safe data-property inspection. | Validation failure code and bounded counters. | Reject before persistence or handler execution. | WP-03 event and ACK parsing tests; adapter manifest validation tests. |
| 10 | Unsafe deserialization | Adapter runtime | Untrusted payload is converted into executable objects or dynamic class/module references. | Code execution or prototype-based privilege manipulation. | JSON-only schemas, no eval/dynamic module loading, no executable manifest fields. | Reject unexpected types, prototypes and accessors. | Disable adapter and discard untrusted runtime state. | WP-04.1 rejects proxy/accessor/unknown fields; runtime not built. |
| 11 | Provider compromise | Provider account and external resources | Provider endpoint or account is compromised. | Data exfiltration or unauthorized mutation. | Minimal scopes, bounded operations, separate credentials and explicit approval for writes. | Provider audit logs, rate anomalies and reconciliation mismatches. | Disable provider adapter and revoke grants; reconcile every in-flight intent. | Provider-specific security controls not verified. |
| 12 | Malicious adapter package | Host process and secrets | Untrusted package is installed or an adapter manifest references arbitrary code. | Arbitrary code execution and secret theft. | No dynamic installation; provenance pin, digest, review and conformance gate before registration. | SBOM, origin and checksum review. | Disable package, revoke all associated grants and rebuild from verified source. | Dynamic package installation is not implemented. |
| 13 | Supply-chain compromise | Build inputs and deployed artifacts | Dependency or build pipeline is compromised. | Trusted adapter artifact is malicious. | Lockfile, pinned dependencies, SBOM, provenance and reproducible build checks. | Dependency/vulnerability scan and artifact digest mismatch. | Quarantine release and rebuild from trusted commit. | Repository lockfile exists; full SBOM/provenance gate pending. |
| 14 | Worker takeover | Execution context and provider credentials | Worker process or host is compromised. | Attacker uses active grants or credentials. | Worker isolation, minimal OS identity, no control-plane mutation rights, resource limits. | Worker identity/lease anomalies and process health. | Fence worker, revoke grant and credential, reconcile started work. | WP-03 lease fencing tested; process isolation not implemented. |
| 15 | Lease token reuse | Delivery authorization and worker ownership | Stale worker reuses a previously issued lease token. | Two workers perform the same side effect. | Database-time expiry, owner binding, monotonic fencing token and exact delivery-start fence. | Fence rejection counter and audit. | Reject stale worker; inspect outbox state; reconcile if delivery already started. | WP-03.9 worker-owner and expiry tests. |
| 16 | TOCTOU authorization race | Policy and delivery boundary | Policy or grant changes between reservation and provider call. | Revoked or stale authorization is used. | Revalidate current authorization and cancellation in the delivery transaction immediately before execution. | Revision mismatch and fence-denial events. | Stop before call; after call start, reconcile rather than assume rollback. | WP-03.9 trust/policy serialization tests. |
| 17 | Policy revision confusion | Approval evidence and policy snapshots | Old policy snapshot is treated as current after a revision change. | Permission survives policy change. | Preserve original snapshot and separately check current authorization revision. | Snapshot/current-revision mismatch audit. | Block new effect; run explicit reconciliation for started work. | WP-03.9 policy revision binding tested. |
| 18 | Audit tampering | Security decision history | Privileged database actor modifies or truncates audit records. | Loss of trustworthy provenance. | Append-only triggers, hash chain, restricted DB roles and external checkpoints. | Full-chain verification and external checkpoint mismatch. | Stop trust-sensitive writes; restore verified backup and preserve forensic copy. | Append-only and hash-chain tests exist; external anchoring pending. |
| 19 | Secret leakage | Credentials, approval material and restricted payloads | Secret is included in manifest, exception, log, metric label or PR body. | Credential theft or sensitive-data disclosure. | Opaque references only, allowlisted audit projection, redaction and log schemas. | Secret-pattern scans and review of structured logs. | Revoke exposed credential; remove exposure through approved incident process. | Capability helper and label-free metrics have tests; full secret broker not implemented. |
| 20 | Resource exhaustion | Workers, queues, database and provider quota | Flood of operations, slow provider or unbounded payload/retry. | Fabric outage or cost spike. | Bounded payload, concurrency, queue, timeouts, attempts and backpressure. | Queue age, timeout, limit and worker saturation metrics. | Circuit-break provider; preserve intents; drain only under bounded policy. | WP-03 retry limits and metric tests; production SLOs not set. |
| 21 | Cross-adapter privilege leakage | Adapter contexts and shared worker | Shared process or mutable context leaks one adapter's credentials/scopes to another. | Adapter B uses adapter A's privileges. | Per-invocation immutable context, isolated credential handles and no shared mutable authority. | Context-binding tests and cross-adapter negative tests. | Terminate affected workers; revoke grants and credentials; reconcile in-flight work. | Runtime isolation and cross-adapter suite pending. |
| 22 | Webhook forgery | Inbound event and ACK endpoint | Attacker sends callback with forged signature, replayed timestamp or wrong raw-body digest. | False state transition or injected event. | Verify signature over exact raw bytes, timestamp, nonce, key lifecycle and event identity. | Signature/replay rejection metrics and audit. | Reject callback; preserve original outbox state; investigate key misuse. | WP-03 ACK crypto tests exist; live webhook endpoint not connected. |
| 23 | Unsafe duplicate retry | External side effect | Worker retries after timeout when provider may already have completed the operation. | Duplicate payment, message or repository mutation. | Provider-specific idempotency proof; UNKNOWN_EXTERNAL_SEMANTICS means one attempt then RECONCILE. | Unknown-outcome and repeated-provider-reference monitoring. | Query provider state or request operator evidence; never blindly resend. | WP-03.9 unknown-to-RECONCILE tests. |
| 24 | Cancellation race | Intent and remote side effect | Cancellation races with worker claim, delivery start, provider response or late ACK. | Cancelled work still executes or late ACK reverses terminal state. | Shared task lock, cancellation/delivery fence, lease token and terminal ACK guard. | Cancellation race audit and late-ACK ledger. | Preserve actual remote result separately; never claim remote rollback. | WP-03.8/03.9 concurrency and late-ACK tests. |
| 25 | Dependency compromise | Runtime and authorization dependencies | Vulnerable or substituted dependency changes parser, crypto, network or storage behavior. | Boundary checks become unreliable. | Lockfile, review, vulnerability scanning, dependency pinning and minimal runtime dependencies. | CI dependency audit and provenance checks. | Pin or roll back to verified dependency set; rerun conformance and security tests. | Lockfile present; comprehensive continuous dependency gate pending. |

## Immediate control decisions

- Do not dynamically load or install adapter code.
- Do not treat adapter contract validation as trust, registration or authorization.
- Do not enable external writes without the existing host authorization and delivery fences.
- Do not claim tenant isolation, production credential security, live STEEL conformance or exactly-once external effects.
- Keep unknown external results in reconciliation until supported by authenticated evidence.
